## Verification

- Used headless Chrome 157 on macOS to render all four viewport widths. Reviewed packaging lettering, the board frame, the four matching sculpts, and the transparent layer edges. The large box title and edition banner remain visible. Fine packaging lettering is difficult to read at mobile size.
- Exercised all three thumbnails by keyboard and pointer at each width. Checked descriptive image names, the single pressed state, status updates, focus retention, and unchanged stage bounds during selection. The smallest thumbnail button measured 91 × 64 CSS px.
- Checked layout order at desktop and mobile widths, measured zero horizontal overflow, and verified that all images decoded and the local display font loaded. No failed local requests or JavaScript errors were recorded during the preview checks.
- Verified the skip link, focus outline, mobile menu opening with Space, Escape and focus return, and the “Learn to play” link. Checked the pressed thumbnail and named stage image in Chrome’s accessibility tree. Other browser engines, physical devices, and manual screen-reader testing were outside this review.
- Ran `node --check` on the preview gallery and shared script, checked Git whitespace, and compared SHA-256 hashes of the existing production page files, approved masters, image exports, and supplied mockup against the pre-edit inventory.
