## Verification

- Reviewed both routes at all four viewport sizes in headless Chrome 157 on macOS, using mobile emulation at 390 and 320 px. The local display font, image elements and card background loaded. Network and console checks found no failed requests or site-authored errors. No horizontal overflow or clipped card text or figures was found. Each card preserved its 8:5 image area.
- Activated all three completed chapter links and “Explore the basics” with Enter and pointer input at every width. The heading appeared in view and the corresponding section received focus. Keyboard activation showed the section outline and Tab continued to the footer. Direct fragment URLs also placed the target heading in view.
- Verified skip links, visible keyboard focus and header and footer current-page indicators on both routes. All four Home-to-Learn links and the Home return links navigated successfully at each width. It also closed on focus departure, outside click, and resize beyond the breakpoint. Keyboard navigation worked between Home and Learn in both directions. Chrome's accessibility tree exposed the unavailable labels when the menu was open.

The footer's layout is preserved farther down the page, with minor raster differences after the shift. Earlier artwork files and the shared script match the starting revision.
- `node --check script.js` and `git diff --check` passed. The review covered Chrome and emulated mobile devices. Other browser engines, physical devices and manual screen-reader testing were outside this pass.
